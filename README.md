# 编程知识地图 · 七份

六门语言/技术（C、C++、Python、MySQL、Linux、HTML）加原有的 Java，一个模子做出来的查表式知识地图。

**入口：`index.html`**（双击打开，七张卡片，每张都能进 HTML 互动版或 Markdown 版）。

## 为什么是这个结构

不是按教科书的章节顺序，而是按「**你要干什么**」组织：

| 层 | 内容 | 回答什么问题 |
|---|---|---|
| 第 0 层 | **基础通用**（10 条） | 这门语言的「常识」：怎么编译、语句怎么结束、哪里有坑 |
| 第 1 层 | **功能域**（11–14 个域，95–124 条功能） | 我想做 X，该用哪个关键字/命令/标签 |
| 跨层 A | **交叉项总表**（7–8 组） | 同一个概念跨了好几个域——从这里能看见全貌 |
| 跨层 B | **备注**（12 条） | 易错点、版本差异、取舍、以及学习顺序 |
| 附 | **一页提纲 / 反向查** | 先扫 18 行看全景；或者从「我要……」反查去哪个域 |

每一行还带两个标注：

- **阶段**：`入门` 先学这个 · `常用` 天天用 · `进阶` 会用就行 · `进阶+` 知道有这回事即可
- **交叉**：这个条目还在哪个域出现（同一概念被重复记录，这是设计，不是冗余）

## 两种形态

- **`.html`**：左侧 sticky 导航（地基 / 功能域 / 跨层三组，带条数）＋ 顶部实时搜索（输入即过滤表格行，右上角显示命中数）＋ `IntersectionObserver` 高亮当前节。深色主题，与 `D:\LMU-CL-Kurse\index.html`、`D:\LMU-Studiengaenge\index.html` 同一套视觉。
- **`.md`**：内容完全一致，方便打印、`git diff`、或在手机上看。

两份由**同一份数据**生成，不会出现「改了 HTML 忘了 md」。

## 第 2 列的小标签（`tagkit.py` 自动判别）

第 2 列原本混着三类东西，现在每条前面有一个小标签说明它的性质——**要你自己写的东西，和能直接查文档抄的东西，是两回事**：

| 语言 | 标签 | 含义 |
|---|---|---|
| Java | 关键字 / 注解 / 标准库 / 写法 | 语言自带的词 / 写在类或方法上的注解 / JDK 现成类 / 语法或思路 |
| C | 关键字 / C 库 / 命令行 / 写法 | 语言关键字 / 标准库函数（include 即可）/ gcc 等命令与选项 / 语法或思路 |
| C++ | 关键字 / STL·库 / 命令行 / 写法 | 同上（STL = include 即可） |
| Python | 关键字 / 内置 / 模块 / 命令行 / 写法 | 内置不用 import；模块要 import；命令行是终端里敲的 |
| MySQL | SQL 关键字 / 函数 / 命令 / 写法 | SQL 语句的关键字 / 可调用函数 / 客户端命令 / 思路 |
| Linux | 命令 / 选项·语法 / 配置·路径 | 要敲的命令 / 重定向等语法 / 路径与配置文件 |
| HTML | 标签 / 属性 / 写法 | `<div>` 这类标签 / `class=` 这类属性 / 语法与思路 |

判别是**规则 + 手工修正**：先看条目名本身（很多名字就是那个词，如 `realloc`、`List`），再看第 2 列的代码；`tagkit.OVERRIDES` 里手工修了约 40 条规则判错的。想看分布：

```powershell
& $py report_tags.py          # 每种语言各标签多少条
& $py report_tags.py --all    # 连每条都列出来
```

改判据只需改 `tagkit.py`（`TAGS` 标签表、`*_KW` / `C_LIB` / `CPP_STL` / `JAVA_JDK` 词表、`OVERRIDES`），不用碰 800 多行数据文件。


## 两个写作纪律（踩过坑）

1. **中文引号用 `「」`**，不要在数据里写 ASCII 双引号——会和张量里的字符串引号打架，`SyntaxError` 且报错位置很误导。修法脚本：`fixquotes.py`（可批量把中文之间的 `"` 换成 `「」` 并 `ast.parse` 自检）。
2. **Markdown 表格里的 `|` 必须转义**（`\|`），否则整张表的列数会错乱。渲染器的 `_c()` 已经处理，`verify_maps.py` 会逐块检查列数。
