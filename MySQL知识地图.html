安装与连接Verbindung

先能连上：服务、端口、账号、客户端工具。

功能关键字 / API用来做什么阶段交叉
服务端与客户端命令mysqld 是服务、mysql 是命令行客户端装 MySQL Server 才有服务；只装 Workbench 连不上入门用户与权限
命令行登录命令mysql -u root -p、-h 主机 -P 端口-p 后不要跟密码（会留在历史里）入门—
默认端口写法3306被占用或改了端口就连不上入门—
看版本与状态SQL 关键字SELECT VERSION();、SHOW STATUS;确认引擎与版本（8.0 vs 5.7 语法有差）常用—
配置文件函数my.ini（Windows）/ my.cnf（Linux）字符集、端口、数据目录都在这里进阶性能与优化
图形客户端命令Workbench / DBeaver / Navicat / VS Code 插件看表结构与数据更快；生产环境慎用「一键删库」常用—
连接串命令mysql://user:pw@host:3306/db写代码时驱动用得到（pymysql/connector）常用—
远程连不上函数检查 bind-address、防火墙、用户 host 是否为 %三者任一为本地就拒外网进阶用户与权限

库与表Schema

建库建表、选对数据类型——类型选错后面全是补丁。

功能关键字 / API用来做什么阶段交叉
建库与切库SQL 关键字CREATE DATABASE db CHARACTER SET utf8mb4;、USE db;字符集在建库时就定好入门—
建表SQL 关键字CREATE TABLE buch (id INT PRIMARY KEY AUTO_INCREMENT, titel VARCHAR(200) NOT NULL);列名、类型、约束一次写清入门约束与设计
常用类型函数INT BIGINT VARCHAR(n) TEXT DATE DATETIME DECIMAL(p,s) TINYINT(1)金额用 DECIMAL，时间用 DATETIME入门—
主键与自增函数id BIGINT PRIMARY KEY AUTO_INCREMENT自增简单高效；分布式才考虑 UUID常用索引
字符集函数utf8mb4 + utf8mb4_0900_ai_ciMySQL 的 utf8 只有 3 字节，存不了 emoji常用—
存储引擎函数ENGINE=InnoDBInnoDB 有事务、行锁、外键；MyISAM 没有常用事务与锁
改表SQL 关键字ALTER TABLE buch ADD COLUMN jahr INT;大表加列会锁表，生产要挑时间进阶性能与优化
看表结构SQL 关键字SHOW TABLES;、DESCRIBE buch;、SHOW CREATE TABLE buch;最后一条能看到完整 DDL 与索引常用—
删表与删库SQL 关键字DROP TABLE、DROP DATABASE不可回滚——先备份入门—

增删改DML

写入数据的三种动作；UPDATE/DELETE 的条件是命门。

功能关键字 / API用来做什么阶段交叉
插入一行SQL 关键字INSERT INTO buch (titel, jahr) VALUES ('Hobbit', 1937);列名写全，避免表结构一变就错位入门—
批量插入SQL 关键字INSERT INTO buch (titel) VALUES ('A'),('B'),('C');一次多行比循环快一个数量级常用性能与优化
更新SQL 关键字UPDATE buch SET jahr = 1937 WHERE id = 1;先 SELECT 同样条件确认命中几行入门—
删除SQL 关键字DELETE FROM buch WHERE id = 1;不带 WHERE 就是清空表入门—
存在则更新SQL 关键字INSERT ... ON DUPLICATE KEY UPDATE n = n + 1计数器、幂等导入常用进阶索引
REPLACE INTOSQL 关键字先删后插会触发删除副作用，慎用进阶—
清空表SQL 关键字TRUNCATE TABLE buch;比 DELETE 快，但不可回滚、重置自增常用—
受影响行数函数ROW_COUNT()、客户端会打印 Rows matched0 行说明条件写错了常用—
在事务里批量改SQL 关键字START TRANSACTION; ... COMMIT;要么全成要么全不成进阶事务与锁

查询基础SELECT

SELECT 的骨架：选列、筛行、排序、限条数。

功能关键字 / API用来做什么阶段交叉
基本骨架SQL 关键字SELECT titel, jahr FROM buch WHERE jahr > 1900 ORDER BY jahr DESC LIMIT 10;书写顺序固定，执行顺序是 FROM→WHERE→SELECT→ORDER→LIMIT入门—
条件组合SQL 关键字AND OR NOT，括号改变优先级AND 比 OR 优先，混用要括号入门—
范围与集合SQL 关键字BETWEEN 1 AND 5、IN (1,2,3)IN 里别放子查询的大结果集常用多表连接
模糊匹配SQL 关键字LIKE 'Hob%'、LIKE '%bit'前置 % 用不上索引常用索引
空值判断SQL 关键字IS NULL / IS NOT NULL= NULL 永远假常用—
去重SQL 关键字SELECT DISTINCT autor FROM buch;DISTINCT 作用于整行组合常用—
排序SQL 关键字ORDER BY jahr DESC, titel ASC多列排序按顺序生效；NULL 默认排最前入门—
分页SQL 关键字LIMIT 20 OFFSET 40深分页很慢，见性能域常用性能与优化
别名SQL 关键字SELECT titel AS 书名让结果列名可读；也给表起短别名入门多表连接

聚合与分组Aggregation

把多行压成一行：计数、求和、分组统计。

功能关键字 / API用来做什么阶段交叉
五个聚合函数函数COUNT SUM AVG MAX MINAVG/SUM 忽略 NULL入门—
COUNT(*) vs COUNT(列)函数前者数行，后者只数该列非 NULL 的行想数总数就用 COUNT(*)常用—
分组SQL 关键字SELECT autor, COUNT(*) FROM buch GROUP BY autor;SELECT 里非聚合列必须出现在 GROUP BY 中入门多表连接
分组后过滤SQL 关键字HAVING COUNT(*) >= 2WHERE 在分组前、HAVING 在分组后常用查询基础
小计与总计SQL 关键字GROUP BY ... WITH ROLLUP多出一行汇总；也可用 UNION 拼进阶—
条件聚合函数SUM(CASE WHEN jahr < 1900 THEN 1 ELSE 0 END)一行里算多个指标，避免多次扫表进阶—
去重计数函数COUNT(DISTINCT autor)比 COUNT(*) 慢，数据量大要考虑预聚合常用—
聚合与 NULL函数SUM 全 NULL 时返回 NULL 而不是 0要 0 用 COALESCE(SUM(x), 0)进阶—

多表连接JOIN

把表按关系拼起来；LEFT JOIN 与「过滤条件放 WHERE 还是 ON」是分水岭。

功能关键字 / API用来做什么阶段交叉
INNER JOINSQL 关键字FROM buch b JOIN autor a ON b.autor_id = a.id只保留两边都匹配的行入门—
LEFT JOINSQL 关键字FROM autor a LEFT JOIN buch b ON ...左表全保留，右表没有就补 NULL常用—
条件放 ON 还是 WHERESQL 关键字LEFT JOIN 的右表条件写 ON 才保留左表放 WHERE 会退化成内连接——最常见的错进阶查询基础
表别名SQL 关键字FROM buch AS b多表时必写，避免歧义入门—
自连接SQL 关键字FROM buch b1 JOIN buch b2 ON b1.autor_id = b2.autor_id同一张表当两张用（找同作者的其他书）进阶—
子查询SQL 关键字WHERE autor_id IN (SELECT id FROM autor WHERE land = 'DE')能写但常比 JOIN 慢；相关子查询更慢常用—
EXISTSSQL 关键字WHERE EXISTS (SELECT 1 FROM ...)只判断存在性，半连接常用进阶—
UNION / UNION ALLSQL 关键字两个结果集上下拼接UNION 去重（有排序开销），能不去重就用 ALL常用—
笛卡尔积SQL 关键字FROM a, b 忘了写连接条件行数 = 两表行数相乘，会把数据库拖死入门性能与优化

索引与执行计划Index

索引用 B+ 树把「扫全表」换成「走树」；建什么索引取决于查询。

功能关键字 / API用来做什么阶段交叉
索引是什么SQL 关键字CREATE INDEX idx_autor ON buch(autor_id);额外的一棵排序树，指向数据行入门—
主键索引函数InnoDB 的主键就是聚簇索引数据和主键存在一起，所以主键要短常用库与表
唯一索引SQL 关键字UNIQUE KEY uk_isbn (isbn)既加速又保证唯一常用约束与设计
联合索引SQL 关键字INDEX idx_a_b (autor_id, jahr)按「最左前缀」生效：能用在 (autor_id)、(autor_id, jahr)进阶—
最左前缀SQL 关键字WHERE jahr = 1937 用不上 (autor_id, jahr)列顺序按「等值在前、范围在后」设计进阶查询基础
覆盖索引写法查询的列全在索引里，就不用回表EXPLAIN 里显示 Using index进阶+性能与优化
EXPLAINSQL 关键字EXPLAIN SELECT ... 看 type/key/rows/Extratype=ALL 是全表扫，ref/range 较好常用性能与优化
索引失效函数列上套函数、隐式类型转换、前置 %、OR 混用这四条能解释九成「明明有索引还是慢」进阶—
不要滥建写法每个索引都拖慢写入、占空间按真实查询建，定期清理不用的常用性能与优化

事务与锁Transaktionen

一组操作要么全成要么全不成；隔离级别决定你能看见别人的什么。

功能关键字 / API用来做什么阶段交叉
ACID写法原子性、一致性、隔离性、持久性InnoDB 用 redo/undo log + MVCC 实现入门—
开始与提交SQL 关键字START TRANSACTION; ... COMMIT; / ROLLBACK;默认 autocommit=1，每条语句自己提交入门—
回滚函数出错就 ROLLBACKDDL 不能回滚（隐式提交）常用—
隔离级别SQL 关键字READ UNCOMMITTED READ COMMITTED REPEATABLE READ（默认）SERIALIZABLE级别越高越安全、并发越低进阶—
三种读异常写法脏读、不可重复读、幻读默认 RR 能挡住前两个，幻读靠间隙锁进阶—
锁的粒度函数行锁（InnoDB）、表锁（MyISAM）没走索引的 UPDATE 可能锁一大片进阶索引
死锁写法两个事务互相等对方的锁SHOW ENGINE INNODB STATUS 看最近一次；重试或统一加锁顺序进阶+—
MVCC 快照写法读不加锁，看到事务开始时的版本所以「读」不会阻塞「写」进阶+—
长事务的危害函数占着 undo、阻塞 DDL、放大死锁概率事务里别做网络请求和等待常用性能与优化

约束与设计Design

用约束把「不可能的数据」挡在数据库外；表结构决定后面好不好查。

功能关键字 / API用来做什么阶段交叉
非空与默认SQL 关键字NOT NULL DEFAULT 0能非空就非空，NULL 会让查询与聚合变复杂入门—
唯一约束SQL 关键字UNIQUE (isbn)业务唯一键要落到数据库常用索引
外键SQL 关键字FOREIGN KEY (autor_id) REFERENCES autor(id)保证引用完整性；高并发系统常在应用层做进阶—
检查约束SQL 关键字CHECK (jahr > 0)8.0.16+ 才真正生效进阶—
三范式函数1NF 原子、2NF 无部分依赖、3NF 无传递依赖先按范式设计，再按查询反范式常用—
反范式函数冗余一列省一次 JOIN要有明确的性能理由，并保证一致性进阶多表连接
主键选择函数自增 BIGINT vs UUID自增短、顺序写入快；UUID 便于分布式但索引更大常用库与表
命名规范函数表名小写下划线、主键统一 id、外键 xx_id统一比「好看」重要入门—
ER 图写法实体—关系—基数先画清楚一对多/多对多，再建表常用—
软删除函数deleted_at 而不是真删查询要处处带条件，别忘进阶—

视图与存储程序Views

把复杂查询封成视图；把逻辑放进数据库要谨慎。

功能关键字 / API用来做什么阶段交叉
视图SQL 关键字CREATE VIEW v_buch AS SELECT ...简化常用查询、限制可见列常用—
视图的代价写法每次查询都重新执行复杂视图套视图会变得很慢进阶性能与优化
存储过程SQL 关键字CREATE PROCEDURE p() BEGIN ... END把多步逻辑放服务端；调试和版本管理更难进阶—
触发器SQL 关键字CREATE TRIGGER ... AFTER INSERT隐式副作用，排错困难——能不用就不用进阶+—
事件调度SQL 关键字CREATE EVENT ... ON SCHEDULE EVERY 1 DAY库内定时任务；要开 event_scheduler进阶+—
函数SQL 关键字CREATE FUNCTION f(x INT) RETURNS INT可在 SQL 里调用；注意确定性标记进阶+—

用户与权限Rechte

最小权限、能备份能恢复——这两件事比会写复杂 SQL 更重要。

功能关键字 / API用来做什么阶段交叉
建用户SQL 关键字CREATE USER 'app'@'%' IDENTIFIED BY '强密码';% 允许远程，localhost 只本地入门安装与连接
授权SQL 关键字GRANT SELECT, INSERT ON db.* TO 'app'@'%';只给需要的权限，别给 ALL常用—
收权SQL 关键字REVOKE DELETE ON db.* FROM 'app'@'%';FLUSH PRIVILEGES 在直接改表时才需要常用—
看权限SQL 关键字SHOW GRANTS FOR 'app'@'%';排查「为什么他能删我不能」常用—
备份命令mysqldump -u root -p --single-transaction db > b.sqlInnoDB 加 --single-transaction 得到一致快照常用—
恢复命令mysql -u root -p db < b.sql先建库再导入；大文件用 source常用—
只备份结构/数据函数--no-data / --no-create-info迁移表结构时很有用进阶—
审计与日志函数general_log、slow_query_log生产只开慢查询日志，general_log 太重进阶性能与优化

性能与优化Performance

先看慢查询日志，再 EXPLAIN，最后才改索引或改 SQL。

功能关键字 / API用来做什么阶段交叉
慢查询日志函数slow_query_log = ON、long_query_time = 1优化的入口：先知道哪条慢常用—
别 SELECT *写法只取需要的列减少 IO，还可能走上覆盖索引入门索引
深分页SQL 关键字LIMIT 100000, 20 会扫掉前 10 万行用「记住上次最大 id」的游标分页进阶查询基础
避免列上运算SQL 关键字WHERE YEAR(datum) = 2026 用不上索引改成范围：datum >= '2026-01-01' AND datum < '2027-01-01'进阶索引
隐式转换写法字符串列传数字会全表扫类型要对齐进阶—
批量写入函数多行 INSERT、或 LOAD DATA INFILE减少往返与事务开销常用增删改
连接池函数应用侧复用连接，别每条 SQL 连一次连接建立比查询还贵进阶—
看连接数SQL 关键字SHOW PROCESSLIST;、max_connections卡住时先看有没有长事务/锁等待常用事务与锁
分表分库写法单表过千万再考虑先优化索引与 SQL，别过早分片进阶+—

交叉项总表 · 同一概念出现在多个域

概念出现在为什么重复出现
索引索引与执行计划「索引是什么」 · 查询基础「模糊匹配」 · 多表连接「连接列要建索引」 · 性能与优化「避免列上运算」「为什么慢」九成是索引问题；建索引、用得上索引、别破坏索引，是三件不同的事
主键库与表「主键与自增」 · 索引与执行计划「主键索引」 · 约束与设计「主键选择」主键同时是约束、是聚簇索引、是设计决策——三处都得想一遍
事务事务与锁「开始与提交」 · 增删改「在事务里批量改」 · 约束与设计「外键」写操作要么成组提交、要么全回滚；约束检查也在事务里发生
字符集库与表「字符集」 · 安装与连接「配置文件」 · 性能与优化「隐式转换」建库时定错字符集，后面每次插入 emoji 都会报错；跨字符集比较还会让索引失效
NULL 的语义查询基础「空值判断」 · 聚合与分组「聚合与 NULL」 · 约束与设计「非空与默认」NULL 表示「未知」，参与比较与聚合都特殊——能非空就非空
分组 + 连接聚合与分组「分组」 · 多表连接「INNER JOIN」 · 聚合与分组「分组后过滤」统计报表几乎都是「先 JOIN 再 GROUP BY」，所以这两个域总一起出现
权限用户与权限「授权」 · 安装与连接「远程连不上」 · 性能与优化「看连接数」连不上、删不掉、看不到——很多「故障」其实是权限

备注 · 易错点 / 取舍 / 顺序

1
UPDATE/DELETE 不带 WHERE 会动全表
先写 SELECT 用同一个 WHERE 看命中行数，再改成 UPDATE。
2
MySQL 的 utf8 只有 3 字节
要存 emoji 与生僻字必须 utf8mb4；建库时就定，后面改很痛。
3
COUNT(col) 不数 NULL
数行数用 COUNT(*)。
4
隐式类型转换让索引失效
字符串列与数字比较、WHERE id = '1' 这类都会。
5
列上套函数让索引失效
YEAR(d) = 2026 → 改成日期范围。
6
LIMIT 深分页很慢
游标分页（WHERE id > 上次最大）才是正解。
7
索引不是越多越好
每个索引都让写入变慢、占空间；按查询建，定期清理。
8
LEFT JOIN 的右表条件写 ON
写进 WHERE 会退化成内连接，把左表不匹配的行滤掉。
9
金额用 DECIMAL
FLOAT/DOUBLE 会有精度误差，钱不能这么存。
10
TRUNCATE 不可回滚
还会重置自增；要能后悔就用 DELETE。
11
DDL 会隐式提交
事务里混 ALTER 会让前面的操作提前提交。
12
学 MySQL 的顺序
①建表与 CRUD ②查询与聚合 ③JOIN ④索引与 EXPLAIN ⑤事务 ⑥权限与备份。
