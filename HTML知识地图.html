文档结构Dokument

每个页面都从同一个骨架开始：声明、语言、编码、标题。

功能关键字 / API用来做什么阶段交叉
<!DOCTYPE html>标签第一行，声明 HTML5少了它浏览器会进怪异模式入门—
<html lang="zh-CN">标签根元素，lang 说明语言影响断词、朗读、翻译提示入门元信息
<head>标签放元信息，不显示在页面上meta/title/link/script 都在这儿入门—
<body>标签放可见内容整页内容都在里面入门—
<meta charset="utf-8">标签必须在 head 前 1024 字节内少了它中文就会乱码入门—
<title>标签浏览器标签页与搜索结果标题每页不同，别都叫「首页」入门元信息
注释写法<!-- 说明 -->不会显示；别在注释里写密码入门—
index.html写法目录的默认首页文件名本地打开文件夹时浏览器认它入门—
<base href>标签统一改相对路径的基准用的人少，容易踩坑进阶+链接与图片

文本与语义Text

标题、段落、强调、列表——这些标签自带「这段文字是什么」的含义。

功能关键字 / API用来做什么阶段交叉
标题标签<h1> … <h6>层级表达结构，不是字号入门可访问性
段落标签<p>一块文字；块级元素，会自动换行入门布局
强调标签<strong>（重要）、<em>（语气）<b>/<i> 只是样式，无语义入门可访问性
换行与分隔标签<br> 换行、<hr> 分隔线<br> 不该用来排版段落间距入门—
无序/有序列表标签<ul><li>…</li></ul>、<ol><li>…</li></ol>导航菜单通常用 ul + a入门布局
定义列表标签<dl><dt>术语</dt><dd>解释</dd></dl>术语表、FAQ常用—
引用标签<blockquote> 块引用、<q> 行内引用配 cite 属性说明来源常用—
代码标签<code> 行内、<pre><code> 代码块pre 保留空白与换行常用—
上下标与删除标签<sub> <sup> <del> <ins>化学式、数学式、修订痕迹常用—
<span>标签行内容器，本身无语义要样式钩子时才用入门布局

链接与图片Links und Bilder

页面之间靠 <a> 连起来，图片靠 <img> 嵌进来——两者的路径规则一样。

功能关键字 / API用来做什么阶段交叉
链接标签<a href="page.html">文字</a>链接文字要说明去哪（别写「点这里」）入门可访问性
相对路径写法./a.html、../img/x.png、/根目录相对的是「当前文件所在目录」入门—
新窗口写法target="_blank" rel="noopener noreferrer"加 rel 防安全与性能问题常用—
页内锚点标签<h2 id="kapitel2"> + <a href="#kapitel2">长文档的目录就靠它常用—
邮件与电话写法mailto:a@b.de、tel:+4989...手机上点了会调起相应 App常用—
图片标签<img src="a.png" alt="描述" width="300">alt 是必填的替代文本入门可访问性
图片格式写法jpg 照片、png 透明/图标、svg 矢量、webp 现代格式矢量图别用 png 导出常用多媒体
图注标签<figure><img …><figcaption>说明</figcaption></figure>比在图片下面写个 p 语义清楚常用—
懒加载写法loading="lazy"长页面的图片延后加载进阶多媒体

表格Tabellen

只用来放「行 × 列」的数据，不要用来排版页面。

功能关键字 / API用来做什么阶段交叉
基本结构标签<table><tr><th>列</th></tr><tr><td>值</td></tr></table>th 表头、td 数据入门—
分区标签<thead> <tbody> <tfoot>便于样式与脚本分段处理常用—
标题标签<caption>表 1：书目</caption>屏幕阅读器会读它常用可访问性
合并单元格写法colspan="2"、rowspan="3"合并后该行少写一个 td常用—
列宽与对齐写法交给 CSS（table-layout、text-align）别用 width 属性堆常用—
scope 属性属性<th scope="col">说明表头管哪一方向进阶可访问性
为什么不用表格排版写法布局该用 CSS Grid/Flex表格布局在窄屏上必然崩入门布局

表单Formulare

让用户输入：每个控件都要有 name（提交时的键）和 label（说明）。

功能关键字 / API用来做什么阶段交叉
<form>标签<form action="/submit" method="post">method 默认 GET，密码必须 POST入门—
<input> 的类型标签text password email number date checkbox radio file range color选对类型就有自带校验与合适键盘入门—
<label>标签<label for="mail">邮箱</label><input id="mail">点标签能聚焦输入框；for 要等于 id常用可访问性
name 与 value属性<input name="email" value="a@b.de">没有 name 的控件不会提交常用—
下拉框标签<select name="land"><option value="de">德国</option></select>multiple 多选、size 显示几行常用—
多行文本标签<textarea name="msg" rows="5"></textarea>内容写在标签之间，不是 value常用—
按钮标签<button type="submit">发送</button>type 默认 submit，别在表单里乱放入门—
校验属性写法required、pattern="[0-9]{5}"、min/max、maxlength浏览器先挡一层，服务端仍必须再验常用—
GET vs POST写法GET 参数在 URL、可被收藏；POST 在请求体查询用 GET，改数据用 POST常用—
文件上传标签<input type="file" accept=".pdf"> + enctype="multipart/form-data"忘了 enctype 文件传不上去进阶—

语义化布局Layout

用有含义的容器描述页面区域，而不是一堆 div。

功能关键字 / API用来做什么阶段交叉
<header>标签页头或区块头可以出现多次（每个 section 一个）入门—
<nav>标签主要导航链接组辅助链接不必用 nav入门—
<main>标签页面唯一主体内容一页只应有一个入门—
<section>标签有主题的一组内容，通常带标题没标题就别用 section常用文本与语义
<article>标签可独立成篇的内容（帖子、卡片）判断标准：单独拿出去还讲得通吗常用—
<aside>标签旁支内容（侧栏、相关链接）不是主体的一部分常用—
<footer>标签页脚、版权、联系方式同样可多次出现入门—
<div> 与 <span>标签无语义的块级/行内容器只在没有更合适的标签时用入门—
文档大纲写法标题层级决定结构，语义标签只是标注区域h1–h6 别跳级常用文本与语义
不要 div 汤标签<div class="header"><div class="nav"> 是反例换成语义标签，CSS 一样能选中常用可访问性

多媒体Medien

音频、视频、嵌入页面——注意格式与加载成本。

功能关键字 / API用来做什么阶段交叉
<video>标签<video src="a.mp4" controls width="640"></video>controls 才有播放条入门—
<audio>标签<audio src="a.mp3" controls></audio>同样需要 controls入门—
多格式回退标签<video><source src="a.webm" type="video/webm"><source src="a.mp4"></video>浏览器挑第一个能播的常用—
字幕标签<track kind="subtitles" src="a.vtt" srclang="de">WebVTT 格式进阶可访问性
<iframe>标签<iframe src="https://…" title="说明"></iframe>嵌外部页面；title 必填常用—
iframe 的代价标签独立文档、样式不继承、可能被 X-Frame-Options 拒能嵌代码就别嵌整页进阶—
poster 与 preload属性poster="封面.jpg"、preload="metadata"首帧不空白、少下载进阶—

属性Attribute

全局属性是所有标签都能用的开关；data-* 是自己造的。

功能关键字 / API用来做什么阶段交叉
id属性页面内唯一锚点、label for、JS 都用它入门脚本接口
class属性可重复、可多个（空格分隔）样式钩子的主力入门—
style标签行内样式调试用，正式样式放 CSS入门—
title标签鼠标悬停提示触屏没有悬停，别放关键信息常用—
data-*写法data-id="42"给自己的 JS/CSS 存数据，合法且不污染语义常用脚本接口
布尔属性写法hidden、disabled、required、checked写名字就为真，hidden="false" 仍是真常用—
lang属性局部语言切换：<span lang="de">多语言页面要标进阶可访问性
tabindex属性0 可聚焦、-1 只能脚本聚焦别用正数打乱 Tab 顺序进阶可访问性
aria-*写法aria-label、aria-hidden、aria-expanded语义标签不够时的补充，不是替代进阶可访问性

可访问性Barrierefreiheit

让屏幕阅读器、键盘用户、色弱用户都能用——这也是 SEO 的基础。

功能关键字 / API用来做什么阶段交叉
alt 替代文本属性<img alt="书封面：Der Hobbit">纯装饰图用 alt=""（不是省略）入门链接与图片
label 关联标签<label for="x"> + id="x"占位符 placeholder 不能替代 label常用表单
键盘可达写法所有交互都能用 Tab + Enter 完成div 加 onclick 默认不可聚焦常用—
用真正的按钮标签<button> 而不是 <div role="button">原生元素自带键盘与语义常用布局
焦点可见写法别 outline: none 了事要自定义就换成更明显的样式常用—
对比度写法正文至少 4.5:1浅灰字最常见的不合格项常用—
标题层级写法h1→h2→h3 不跳级屏幕阅读器按层级导航入门文本与语义
aria-* 基础写法aria-label（无可视文字时）、aria-hidden="true"（装饰）原生语义优先，ARIA 是补丁进阶属性
语言标注标签<html lang> 与局部 lang朗读发音依赖它进阶文档结构

元信息与 SEOMeta

<head> 里的东西决定分享卡片、手机缩放、搜索引擎摘要。

功能关键字 / API用来做什么阶段交叉
viewport标签<meta name="viewport" content="width=device-width, initial-scale=1">不加手机端会缩成一小块入门文档结构
description标签<meta name="description" content="一句话摘要">搜索结果里的摘要常用—
Open Graph属性<meta property="og:title" content="…">、og:image、og:description微信/Twitter 分享卡片的来源常用—
canonical标签<link rel="canonical" href="https://…">多 URL 指向同一内容时告诉搜索引擎哪个是正本进阶—
favicon标签<link rel="icon" href="favicon.ico">标签页小图标常用—
robots标签<meta name="robots" content="noindex">测试页别被收录进阶—
lang 与字符集属性<html lang> + <meta charset>双重影响索引与朗读入门文档结构

与 CSS/JS 的接口CSS und JS

HTML 提供结构，CSS 与 JS 通过选择器和 DOM 挂上来。

功能关键字 / API用来做什么阶段交叉
引入样式标签<link rel="stylesheet" href="style.css">放 head 里；内联 <style> 只用于关键样式入门—
引入脚本标签<script src="app.js" defer></script>defer 等解析完再按顺序执行常用—
defer vs async属性defer 保序、async 谁先下载完谁先跑操作 DOM 的脚本用 defer进阶—
选择器从哪来属性id → #x、class → .x、标签 → p、属性 → [data-id]CSS 与 JS 都靠这些钩子常用属性
DOM 查询写法document.querySelector("#x")、querySelectorAll现代写法，比 getElementById 通用常用—
事件写法btn.addEventListener("click", fn)别用 onclick="..." 行内写法常用—
改了 DOM 才看得见写法el.textContent = "新"、el.classList.add("on")改 class 比改 style 好维护常用—
表单与校验属性form.checkValidity()、submit 事件里 preventDefault()前端校验只为体验，服务端必须再验进阶表单

交叉项总表 · 同一概念出现在多个域

概念出现在为什么重复出现
alt 替代文本链接与图片「图片」 · 可访问性「alt 替代文本」 · 多媒体「字幕」图片、图表、视频都要有文字替代；这是「看不见的人也能用」的第一道门
语义标签文本与语义「强调」 · 语义化布局「<main>」 · 可访问性「用真正的按钮」语义不是风格问题：它决定屏幕阅读器怎么念、搜索引擎怎么理解、键盘能不能用
表单控件与标签表单「<label>」 · 可访问性「label 关联」 · 与 CSS/JS 的接口「表单与校验」一个 input 要同时被 label 关联、被 CSS 选中、被 JS 读到——三处都靠 id/name
属性钩子属性「data-*」 · 与 CSS/JS 的接口「选择器从哪来」 · 可访问性「aria-* 基础」id/class/data-*/aria-* 都是「挂东西的地方」，但只有前两个该用于样式
加载与顺序文档结构「<head>」 · 与 CSS/JS 的接口「defer vs async」 · 多媒体「懒加载」谁先下载、谁先执行决定了「为什么脚本拿不到元素」这类问题
标题层级文本与语义「标题」 · 语义化布局「文档大纲」 · 可访问性「标题层级」h1–h6 同时是视觉层级、文档大纲、和屏幕阅读器的导航结构
路径链接与图片「相对路径」 · 文档结构「<base href>」 · 多媒体「<iframe>」相对路径以「当前文件」为基准，所以同一段 ../img/a.png 在不同深度的页面里指向不同位置

备注 · 易错点 / 取舍 / 顺序

1
漏闭合标签浏览器不会报错
它会自己猜，结果往往不是你想要的。写完用 validator.w3.org 过一遍。
2
<img> 一定要有 alt
装饰图写 alt=""（空但存在），不是不写。
3
表格只放数据
布局用 CSS Grid/Flex；表格布局在手机宽度下必崩。
4
placeholder 不是标签
它一输入就消失，不能替代 <label>。
5
type 选对省一半校验
type="email"、type="number"、required 都是免费的。
6
相对路径以文件位置为准
css/a.css 里的 url(../img/x.png) 相对的是 CSS 文件，不是 HTML。
7
忘了 viewport 手机端会缩小
整页缩成一小块，用户要放大才能读。
8
defer 比放在 </body> 前更明确
两者都能保证 DOM 就绪，但 defer 语义更清楚。
9
中文乱码 = 缺 <meta charset>
或者文件本身没存成 UTF-8。
10
<div> + onclick 不是按钮
键盘用户按不到；用 <button>。
11
target="_blank" 要配 rel
noopener noreferrer，否则新页面能操作原页面。
12
学 HTML 的顺序
①骨架与文本 ②链接与图片 ③列表与表格 ④表单 ⑤语义布局 ⑥可访问性 ⑦与 CSS/JS 接口。
